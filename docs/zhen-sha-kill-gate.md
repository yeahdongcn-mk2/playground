## 工程评估

### 评估口径

- 生产文件数 / 生产行数只统计 `src/games/zhen-sha/` 下**参与构建**的 `.ts` 与 `.css`，排除 `*.test.ts`（以及测试辅助文件）。
- `src/games/registry.ts` 的入口单独列出，不混入原型的生产文件数 / 行数。
- 行数按文件的换行符计数，与 `wc -l` 一致。
- 完整特性规模是估算，不是实测；依据 #246、#247、#248、#249 的范围与现有五款游戏的规模，误差约 ±10%。

### 新概念（2 个）

1. **固定步长实时弹反判定**：以 `1000/120` ms 的整数 tick 推进，点按格挡、长按蓄势、松手棍击；完美 / 普通 / 落空判定窗是导出常量，势满破防，三次中招结束；同一输入序列在 60Hz / 120Hz 的帧块切分下结果逐项相同。仓库现有五款游戏没有实时判定循环。
2. **无素材的程序化水墨 Canvas 表现与手势输入**：黑宣纸、墨晕、飞白、朱印、金色棍弧全部由 Canvas 2D / CSS 代码生成，不引入图片或字体文件；Pointer Events 把轻点 / 长按 / 松手映射到引擎动作，并在 reduced-motion 下保留判定反馈。

新概念数：2

程序化水墨是本评估第 2 个概念的一部分，不单列。若评审要求把「程序化水墨」单列为第三个新概念，则概念数为 3，本评估必须按 L 复核（见结论）。

### 可自动验收面

- 固定步长与确定性：`engine.test.ts` 覆盖 120Hz 单步、60Hz / 120Hz / 抖动帧块切分下完美数、中招数、势与分数逐项相等。
- 判定与状态：完美 / 普通 / 落空边界 ±1 tick、势累积、三次完美破防、破防窗口首末 tick、蓄势 / 松手终结、三次中招失败、`restart()`、快照隔离。
- 引擎边界：`engine.ts` 不引用 `document` / `window` / `Phaser` / `THREE` / `setTimeout` / `Date.now`，由源码约束测试守护。
- 视图与手势：`zhen-sha-view.test.ts`（jsdom）覆盖轻点 / 长按 / 松手到引擎输入的映射、HUD 随快照更新、结算与重开、pointer capture 丢失、destroy / abort 的监听与 rAF 清理、页面隐藏暂停、音效事件映射。
- 入口与路由：懒加载入口不把 view / engine 拉进 shell 包；`#/games/zhen-sha` 可从大厅进入；320×640 首屏三手势提示由 `tests/e2e/zhen-sha.spec.ts` 断言。
- 构建与预算：`npm run typecheck`、`npm run lint`、`npm run test:unit`、`npm run build`、`npm run check:budget` 可重复执行。
- 风格层可自动化的部分：核心色数量、`prefers-reduced-motion` 分支、无外部图片 / 字体 / URL 的 grep 约束，可在后续卡补测试。
- 本评估文档自身由 `kill-gate-doc.test.ts` 校验：文件数 / 行数必须与生产文件一致，结论、#261、试玩状态与「未新增系统」陈述必须存在。

### 不可自动验收面

- **3 人盲测试玩**：是否 ≥2 人完成 ≥3 次完美弹反、3 人能否用自己的话表达「等对方出手再按」、0 人把动作描述成「一直点 / 连点」、是否有人报「点不动」。这些必须由真实的人试玩并逐字记录，自动测试不能代替。
- **手感**：60–120ms 顿帧、棍影、音效与触感是否让「按下去的那一下」成立；截图和 DOM 断言只能证明状态与像素存在，不能证明手感。
- **风格可读性**：水墨 / 武侠 / 红金气质是否被未看设计说明的人识别，是否有人觉得像卡牌 / 表格；#249 另有人工指认。
- **学习成本**：60 秒内能否无需解释学会三种手势；只能由试玩观察。
- **真实设备触感与低端机性能**：Playwright 设备模拟能覆盖布局与事件路径，但不能替代真实手机上的触感、延迟与帧率感受。

### 未新增的系统

- 没有新增物理、音频、3D 或实体池：判定只发生在固定步长的整数 tick 上，不进入物理世界；音效只复用 `GameServices.audio` 已有的 7 个合成事件，不新增音频文件；画面是 Canvas 2D 与 CSS，不引入 Three.js / WebGL；画面按快照与固定数组重绘，不维护实体池 / 对象池。

### 结论

对照 #250 的 S/M/L 尺子（M 的复核区间：7–9 个文件、1,400–2,200 行、2 个新概念）：

- 文件数：原型 4 个；完整特性估算 7 个，落在 M 区间下沿。
- 行数：原型 1,416 行；完整特性估算约 2,154 行，落在 M 区间内。
- 新概念：2 个，符合 M。

**结论：M。** 后续卡可按 M 规模继续。行数已接近 2,200 行上沿：实现中若超过 2,200 行，或出现第三个新概念，必须回到本文按 L 复核。

程序化水墨的敏感度：本评估把它归入第 2 个「程序化水墨 Canvas 表现与手势输入」概念，所以概念数为 2。若评审要求把「程序化水墨」单列为第三个新概念，则概念数为 3，本评估必须按 L 复核；届时停止后续卡，只保留 kill gate 记录。
