# 贪食蛇设计与测试计划

> 第一款游戏的作用有两个：给玩家一个完整可玩的作品，同时证明“共享外壳 + Phaser 4”这套底座真的能承载一个游戏。

## 1. 玩法目标

- **经典、即时、低门槛**：打开即玩，方向键即可操作，不需要教程。
- **一局 30 秒到 5 分钟**：短局可重开，长局靠加速制造紧张感。
- **有明确成长**：分数、长度、最高分、速度都实时可见。
- **全端可玩**：桌面键盘、移动端触屏 D-pad、滑动都支持。

## 2. 规则

| 项目 | 规则 |
| --- | --- |
| 棋盘 | 20 × 20 网格，四周是墙 |
| 初始蛇 | 长度 3，位于棋盘中央，向右移动 |
| 果实 | 每次随机出现在空格；吃到后蛇增长 1 格，得分 +10 |
| 速度 | 初始每步 150 ms；每吃一个果实减少 6 ms，最低 70 ms |
| 死亡 | 撞墙或撞到自己的身体 |
| 胜利 | 蛇填满整个棋盘（20 × 20 = 400 格） |
| 暂停 | 空格 / P / Esc / 按钮 |
| 重开 | R / 按钮 / 结束覆盖层 |
| 最高分 | 按浏览器保存（localStorage），实时刷新 |

速度公式：

```
stepMs = clamp(150 - 6 × foodEaten, 70, 150)
```

转向规则：

- 不能 180° 反向；
- 同一 tick 只消费一个转向；
- 最多缓存 2 个转向，支持快速“上 → 左”过弯；
- 尾部会在本 tick 移开，因此“追尾”是合法操作。

## 3. 状态机

```
        start()                 pause()
ready ─────────▶ running ◀──────────── paused
                   │  ▲                    │
                   │  └──── resume() ──────┘
                   │
         撞墙/撞自己│             填满棋盘
                   ▼                 ▼
               gameover            won
                   └──── restart() ────┘
                         ready
```

- `restart()` 只重置状态，不自动开始；UI 的“再来一局”会紧接着 `start()`。
- 暂停时计时器不累积；切到后台会自动暂停。
- 结束后所有输入（除重开）无效。

## 4. 操作

| 输入 | 行为 |
| --- | --- |
| ↑ ↓ ← → / W A S D | 转向 |
| 空格 / Enter | 开始、暂停/继续、结束后重开 |
| P / Esc | 暂停/继续 |
| R | 立即重开 |
| 触屏 D-pad | 转向；中间按钮开始/暂停 |
| 在棋盘上滑动 | 按方向转向 |
| 站点头部音效按钮 | 全局静音/开启，跨游戏持久化 |

## 5. 技术结构

### 5.1 纯逻辑引擎（`engine.ts`）

职责：

- 维护蛇、食物、方向、分数、速度、状态；
- 处理移动、生长、碰撞、胜利；
- 用注入的 `rng` 生成食物，方便确定性测试；
- 暴露不可变快照 `SnakeSnapshot`，渲染层无法反向修改状态；
- 支持自定义初始布局（`initialSnake` / `initialFood`），用于边界测试与未来的解谜模式。

不依赖 DOM、Phaser、计时器或存储。单步推进由渲染层按 `stepMs` 驱动。

### 5.2 Phaser 场景（`scene.ts`）

- 两层 Graphics：静态棋盘 + 动态蛇/果实；
- 20×20 网格，逻辑画布 640×640，Phaser `Scale.FIT` 自适应；
- 蛇身从尾到头绘制，头部更亮并带朝向眼睛；
- 果实有呼吸脉冲；死亡时镜头轻震，胜利时闪屏（尊重 `prefers-reduced-motion`）；
- 键盘监听在场景内，销毁时由 Phaser 统一清理。

### 5.3 DOM 外壳（`snake-view.ts`）

- HUD：得分、最高分、长度、速度；
- 覆盖层：READY / PAUSED / GAME OVER / PERFECT；
- 按钮、D-pad、滑动、可见性暂停；
- 最高分持久化（`playground:v1:snake.highscore`）；
- 音效事件：开始、吃、死亡、胜利、暂停；
- `aria-live` 播报状态变化；
- 开发环境测试接缝（见 §7）。

输入去重：Phaser 4 的键盘队列要到下一个 game step 的 `postUpdate` 才清空，如果两个按键在同一帧内到达，早先的 keydown 可能被再次派发。场景用 `WeakSet<KeyboardEvent>` 记住已处理的原生事件，避免快速“转向上 + 转向左”时第一个转向被应用两次。

## 6. 视觉与动效

- 深色底 + 网格 + 荧光绿蛇，呼应“街机”主题；
- 蛇头亮黄绿、身体向尾部渐变到深绿；红色果实带柔光；
- 字体使用系统字体栈，避免额外网络请求；
- 页面外壳用网格背景、玻璃面板和大标题建立“游戏厅”气质；
- 桌面为“棋盘 + 侧栏”，窄屏自动改为单列并把 D-pad 放在棋盘下方；
- 所有动效在 `prefers-reduced-motion` 下关闭。

## 7. 测试计划

### 7.1 单元测试（Vitest，17 个用例）

| 分组 | 覆盖 |
| --- | --- |
| 初始状态 | 长度、位置、方向、分数、食物不在蛇身 |
| 基础移动 | 每 tick 前进一格 |
| 转向 | 拒绝反向、快速双转向按顺序生效、非运行状态忽略 |
| 进食 | 增长、+10 分、速度提升、刷新食物 |
| 碰撞 | 撞墙、撞自己、尾随合法 |
| 胜利 | 填满棋盘触发 `won` |
| 状态 | 暂停/继续、重开重置、快照防御性复制 |
| 配置 | 非法棋盘/长度/布局抛错 |
| 随机 | 同种子食物一致、四方向初始蛇都在界内 |

### 7.2 端到端测试（Playwright）

| 场景 | 断言 |
| --- | --- |
| 大厅 | 标题、游戏卡、规划卡、无控制台错误 |
| 进入/返回 | 点击卡片进入游戏、Canvas 出现、返回大厅后 Canvas 销毁 |
| 开始/暂停 | 空格开始/暂停/继续；P、Esc 分别切换暂停；覆盖层文案正确 |
| 吃果实 | 通过 `?food` 固定首果位置，HUD 分数从 0 → 10，最高分落库 |
| 游戏结束 | 向上撞墙，出现 GAME OVER，重开后分数归零、状态 running |
| 最高分 | 预置 localStorage，HUD 显示正确；更高分不被低分局覆盖；更低分被新纪录覆盖 |
| 移动端 | D-pad 在棋盘下方可见，点击方向开始游戏并改变朝向；无横向溢出 |
| 滑动 | 在棋盘上滑动会转向 |
| 页面隐藏 | 自动暂停并显示暂停覆盖层 |
| 音效设置 | 关闭后 `aria-pressed=false`，刷新后保持 |

### 7.3 手工验收清单

- [ ] 桌面 Chrome/Safari/Firefox 可玩；
- [ ] 手机实际触摸滑动与 D-pad 顺手；
- [ ] 暂停后切标签页再回来不会“偷跑”；
- [ ] 最高分在刷新后仍在；
- [ ] 键盘焦点可见，Tab 可到达所有按钮；
- [ ] 慢速网络下大厅先出现，游戏 chunk 加载有 loading 态。

## 8. 已知限制与后续

- 固定 20×20，无穿墙模式、障碍物、特殊道具；
- 最高分只在本浏览器；
- 没有在线排行榜、回放或观战；
- 音效为合成音，没有音乐；
- 速度曲线是单一线性加速，未来可加入难度选择或自适应难度。

这些限制都是玩法/平台扩展，不影响当前“完整可玩一局”的交付。
